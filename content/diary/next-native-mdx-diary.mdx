The goal for this diary is intentionally small: local files, static routes, and a rendering path that belongs to the framework already running the site.

## Why MDX

MDX keeps entries close to the code that renders them. It also means examples can live beside prose without introducing a CMS, separate metadata parser, or runtime renderer.

```mdx
import { defineDiaryEntry } from "@/lib/diary/metadata";

export const metadata = defineDiaryEntry({
  title: "Building a Next-Native MDX Diary",
  description: "A static MDX diary setup for Next.js.",
  publishedAt: "2026-06-13",
  tags: ["nextjs", "mdx", "systems"],
});
```

That shape keeps metadata in the entry file while the slug remains filename-derived.

## Static by default

The public routes are generated from published entries only. Drafts stay importable for local work, but they do not appear in the index, RSS feed, sitemap, or generated entry routes.
